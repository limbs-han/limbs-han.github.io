약관 하나의 오류로 멈추던 수집과 승인 전 데이터의 분리

문제와 원인
정확한 추천에는 카드 약관 확보가 먼저였습니다. 전체 대상 대비 수집 비율을 확인하니 누락이 남아 실행 기록을 대조하도록 요청했습니다. PDF 변환 오류가 수집기 프로세스 전체를 종료시키면서 뒤의 카드까지 수집되지 않는 문제였습니다.
선택과 실행
한 파일의 실패가 전체 수집을 막지 않도록 변환 작업을 별도 프로세스로 분리해 재수집했습니다. 실행 기록 제공과 수집 범위 확인, 개선 결과 대조를 직접 진행하고 AI 도구로 원인 분석과 코드를 구현했습니다.
판단 기준
약관을 확보해도 LLM이 추출한 문장을 곧바로 금액 계산에 쓸 수는 없었습니다. 원문, 추출 초안, 검수 기록과 승인 결과를 나누고, 원문과 대조해 승인한 정보만 계산 데이터에 반영하도록 설계했습니다.
  1. 원문 수집변경된 원문 구분
  2. LLM 추출 초안확정 데이터와 분리
  3. 원문 대조와 승인사람의 확인 단계
  4. 승인 결과 반영중복 없이 MERGE

원문 확보율 95.0% → 99.3%당시 판매 중 개인 카드 1,846장 기준입니다. 추출 정확도와 구분하며, 승인 결과를 반영하는 파이프라인은 운영 환경에 배포했습니다.

결과
187건 중 170건의 계산 결과가 일치했습니다. 나머지 17건은 미표시 할인, 카드사의 업종 판정, 이전 이용 정보 부족 등으로 구분해 기록했습니다. 확인 정보가 부족한 거래까지 정확하다고 간주하지 않았고, 대조 가능한 범위에서는 엔진 오류가 확인되지 않았습니다.

명세서 대조는 초기 Python 계산 엔진의 검증 기록입니다. 현재 앱의 Dart 계산 엔진과 SQLite 저장 구조와 구분합니다.
